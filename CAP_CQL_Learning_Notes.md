# CAP CQL Learning Notes

## 1. CQL to SQL Mapping

### Your Query Example
```javascript
const authorIdAndBookCountArray = await SELECT.from(Books)
  .columns('author_ID', { func: 'count' })
  .where({ author_ID: { in: ids } })
  .groupBy('author_ID');
```

### Equivalent SQL
```sql
SELECT author_ID, COUNT(*) AS count
FROM Books
WHERE author_ID IN (?, ?, ...)
GROUP BY author_ID;
```

### CQL Building Blocks

| CQL Method | SQL Equivalent | Purpose |
|------------|----------------|---------|
| `SELECT.from(Entity)` | `FROM Entity` | Start query |
| `.columns(...)` | `SELECT ...` | Select columns/expressions |
| `.where({...})` | `WHERE ...` | Filter conditions |
| `.groupBy(...)` | `GROUP BY ...` | Grouping |
| `.orderBy(...)` | `ORDER BY ...` | Sorting |
| `.limit(n)` | `LIMIT n` | Pagination |

### Key Patterns in Your Code

**Update with expression:**
```javascript
UPDATE(Books).set({ 
  price: { func: 'ROUND', args: [{ xpr: [{ ref: ['price'] }, '*', { val: 0.9 }] }, { val: 2 }] } 
})
-- SQL: UPDATE Books SET price = ROUND(price * 0.9, 2)
```

**Update with operator:**
```javascript
.set({ stock: { '+=': 1 } })
-- SQL: SET stock = stock + 1
```

**Where operators:**
```javascript
.where({ author_ID: { in: ids } })        // IN
.where({ ID: bookId })                    // =
.where({ price: { '>': 20 } })            // >
.where({ title: { like: '%Java%' } })     // LIKE
```

## 2. Why COUNT(*) is Needed

`COUNT(*)` counts the number of books **per author** — that's the whole point of the query.

**With COUNT(*)** → gives you: author_ID + how many books they wrote
```sql
SELECT author_ID, COUNT(*) 
FROM Books 
WHERE author_ID IN (...) 
GROUP BY author_ID;
-- Result: { author_ID: '1', count: 5 }, { author_ID: '2', count: 3 }
```

**Without COUNT(*)** → gives you: one row per book (not useful here)
```sql
SELECT author_ID 
FROM Books 
WHERE author_ID IN (...) 
GROUP BY author_ID;
-- Result: { author_ID: '1' }, { author_ID: '2' }  (no counts!)
```

The `GROUP BY author_ID` collapses all books by the same author into one row. `COUNT(*)` tells you **how many rows were collapsed** — i.e., how many books that author has.

## 3. CQL is Database-Agnostic (SQLite → HANA → PostgreSQL)

### How It Works
```
Your CQL Code → CAP Runtime → Database-Specific SQL
```

| Environment | What Happens |
|-------------|--------------|
| **Local (SQLite)** | CAP translates CQL → SQLite SQL |
| **Cloud (HANA)** | CAP translates CQL → HANA SQL (HANA dialect) |
| **Other DBs** | CAP has adapters for PostgreSQL, etc. |

### Configuration (package.json)
```json
{
  "cds": {
    "requires": {
      "db": {
        "kind": "sqlite",      // local dev
        "kind": "hana",        // production (S/4HANA)
        "kind": "postgres"     // alternative
      }
    }
  }
}
```

**You write CQL once. CAP generates the right SQL for the target DB.** No code changes needed when moving from SQLite → HANA.

## 4. Dialect Differences: SQLite vs HANA vs PostgreSQL vs Oracle vs SQL Server

### Pagination
```javascript
SELECT.from(Books).limit(10).offset(20)
```

| Database | Generated SQL |
|----------|---------------|
| **SQLite** | `SELECT * FROM Books LIMIT 10 OFFSET 20` |
| **HANA** | `SELECT * FROM Books LIMIT 10 OFFSET 20` |
| **PostgreSQL** | `SELECT * FROM Books LIMIT 10 OFFSET 20` |
| **Oracle** | `SELECT * FROM Books OFFSET 20 ROWS FETCH NEXT 10 ROWS ONLY` |
| **SQL Server** | `SELECT * FROM Books ORDER BY (SELECT 0) OFFSET 20 ROWS FETCH NEXT 10 ROWS ONLY` |

### Date Functions (Last 30 Days)
```javascript
SELECT.from(Books).where({ 
  publishedAt: { '>': { func: 'sub', args: [{ func: 'now' }, { val: 30 }, { val: 'day' }] } } 
})
```

| Database | Generated SQL |
|----------|---------------|
| **SQLite** | `WHERE publishedAt > date('now', '-30 days')` |
| **HANA** | `WHERE publishedAt > ADD_DAYS(CURRENT_DATE, -30)` |
| **PostgreSQL** | `WHERE publishedAt > CURRENT_DATE - INTERVAL '30 days'` |
| **Oracle** | `WHERE publishedAt > SYSDATE - 30` |

### String Concatenation
```javascript
SELECT.from(Books).columns({ func: 'concat', args: [{ ref: ['title'] }, { val: ' - ' }, { ref: ['author_name'] }] })
```

| Database | Generated SQL |
|----------|---------------|
| **SQLite/HANA/PostgreSQL/Oracle** | `SELECT title || ' - ' || author_name FROM Books` |
| **SQL Server** | `SELECT title + ' - ' + author_name FROM Books` |

### Auto-increment / Identity
```cds
entity Books {
  key ID : Integer @(autoIncrement: true);
  title : String;
}
```

| Database | DDL Generated |
|----------|---------------|
| **SQLite** | `ID INTEGER PRIMARY KEY AUTOINCREMENT` |
| **HANA** | `ID INTEGER GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY` |
| **PostgreSQL** | `ID SERIAL PRIMARY KEY` |
| **Oracle** | `ID NUMBER GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY` |

### UUID Generation
```javascript
INSERT.into(Books).columns('ID', 'title').values({ func: 'uuid' }, 'New Book')
```

| Database | Generated SQL |
|----------|---------------|
| **SQLite** | `VALUES (lower(hex(randomblob(16))), 'New Book')` |
| **HANA** | `VALUES (NEWID(), 'New Book')` |
| **PostgreSQL** | `VALUES (gen_random_uuid(), 'New Book')` |
| **Oracle** | `VALUES (SYS_GUID(), 'New Book')` |

### Upsert
```javascript
UPSERT.into(Books).entries({ ID: 1, title: 'Updated', stock: 10 })
```

| Database | Generated SQL |
|----------|---------------|
| **SQLite/PostgreSQL** | `INSERT ... ON CONFLICT(ID) DO UPDATE SET ...` |
| **HANA** | `UPSERT Books ... WITH PRIMARY KEY` |
| **Oracle** | `MERGE INTO Books USING DUAL ON (ID=1) ...` |

## 5. Node.js in CAP — Simple Explanation

**Node.js** = JavaScript runtime that runs **on the server** (not in the browser).

| Context | Where JS Runs | What It Does |
|---------|---------------|--------------|
| **UI5 (your background)** | Browser | Renders UI, calls APIs |
| **CAP / Node.js** | Server (backend) | Handles requests, talks to DB, runs business logic |

### CAP Architecture (MVC Analogy)

```
┌─────────────────────────────────────────────────────────────┐
│                      CAP Application                        │
├─────────────────┬─────────────────────┬─────────────────────┤
│   Model (CDS)   │   View (optional)   │   Controller (Node) │
│  - Entities     │  - Fiori/UI5 apps   │  - Service handlers │
│  - Services     │  - REST/OData       │  - Custom logic     │
│  - Annotations  │  - API consumers    │  - Event handlers   │
└─────────────────┴─────────────────────┴─────────────────────┘
```

**Your `srv/service.js` = Controller layer**
- `this.on('READ', ...)` → event handlers (like controller methods)
- `SELECT/UPDATE/INSERT` → model operations (via CQL)
- Runs on **Node.js server**, not browser

### What You Already Know (Transferable)

| UI5 Concept | CAP/Node.js Equivalent |
|-------------|------------------------|
| Controller `onInit` | Service `init()` |
| Event handlers (`onPress`) | `this.on('READ', ...)` |
| Model binding | CQL queries (`SELECT.from()`) |
| OData calls | CAP *exposes* OData automatically |
| `sap.ui.define` modules | `import` / `require` (ES modules) |

## 6. Complete Request Flow: UI5 → CAP → Database

```
┌──────────────┐     HTTP/HTTPS      ┌──────────────────┐     Internal      ┌──────────────┐
│   BROWSER    │ ──────────────────► │   NODE.JS SERVER │ ────────────────► │  DATABASE    │
│   (UI5 App)  │   OData/REST API    │   (CAP Runtime)  │   SQL/Protocol    │ (SQLite/HANA)│
└──────────────┘                     └──────────────────┘                   └──────────────┘
```

### Step-by-Step

#### 1. Browser (UI5)
```javascript
// UI5 Controller
this.getModel().read("/Authors", {
  success: (data) => { this.getView().setModel(data, "authors") }
})
```
→ Generates HTTP: `GET https://your-cap-app.com/odata/v4/BookStore/Authors`

#### 2. Network
- Protocol: HTTPS (production) / HTTP (local)
- Format: OData V4 (JSON)
- Auth: JWT/OAuth (XSUAA in Cloud Foundry)

#### 3. Node.js Server (CAP Runtime)
```
Request arrives at Node.js process
         │
         ▼
┌────────────────────────────────────┐
│  @sap/cds Server (Express-based)   │
│  • Router matches /odata/v4/...    │
│  • Parses OData query options      │
│  • $filter, $select, $expand, etc. │
└────────────────────────────────────┘
         │
         ▼
┌────────────────────────────────────┐
│  Authentication & Authorization    │
│  • Validates JWT token             │
│  • Checks @requires annotations    │
│  • Injects req.user, req.authInfo  │
└────────────────────────────────────┘
         │
         ▼
┌────────────────────────────────────┐
│  YOUR SERVICE HANDLERS (service.js)│
│  this.before('READ', Books, ...)   │  ← Modify query, add filters
│  this.on('READ', Books, ...)       │  ← Custom logic, override default
│  this.after('READ', Authors, ...)  │  ← Enrich results (your bookCount!)
│  CQL executed: SELECT.from(...)    │
└────────────────────────────────────┘
         │
         ▼
┌────────────────────────────────────┐
│  CAP CQL → Native SQL Translation  │
│  • Dialect-specific (SQLite/HANA)  │
│  • Parameter binding (security)    │
│  • Connection from pool            │
└────────────────────────────────────┘
```

#### 4. Database
| Local Dev | Production (S/4HANA) |
|-----------|---------------------|
| SQLite file (`db.sqlite`) | HANA Cloud / HANA on-premise |
| Auto-created by `cds deploy` | Provisioned via Cloud Foundry service |

### Your Code in This Flow
```javascript
// srv/service.js — Runs INSIDE Node.js process

this.after('READ', Authors, async (data) => {
  // 1. data = array of authors from DB
  const ids = data.map(obj => obj.ID)
  
  // 2. Another CQL → SQL → DB roundtrip
  const authorIdAndBookCountArray = await SELECT.from(Books)
    .columns('author_ID', { func: 'count' })
    .where({ author_ID: { in: ids } })
    .groupBy('author_ID')
  
  // 3. Enrich original data (runs in Node.js memory)
  for (const obj of data) {
    const match = authorIdAndBookCountArray.find(a => a.author_ID === obj.ID)
    obj.bookCount = match?.count ?? 0
  }
  
  // 4. Returns enriched data → JSON → HTTP response → UI5
})
```

## 7. Key Insight for UI5 Developers

| UI5 Pattern | CAP Equivalent |
|-------------|----------------|
| `model.read("/Authors")` | HTTP GET `/odata/v4/BookStore/Authors` |
| `formatter` function | `after` handler (enrich data) |
| `sorter`/`filter` in binding | `$orderby`/`$filter` in URL (handled automatically) |
| `attachRequestCompleted` | `after` handler / middleware |
| Local JSONModel | Database entities (persistent, shared) |
